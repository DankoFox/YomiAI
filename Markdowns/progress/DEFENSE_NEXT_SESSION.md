## The Open Vulnerability (Must Fix Before Defense)

**Problem:** The "SASRec" row in the comparison table is currently an ablation of our own model (pretrained DIF-SASRec with α forced to 0 at inference). A committee member will note that:
- The model was trained WITH category auxiliary loss, so the weights are shaped by it even when α=0
- It is NOT a reimplementation of Kang & McAuley 2018 SASRec trained from scratch
- Calling it an "external comparison" is indefensible

**Consequence:** The table currently proves category decoupling helps (valid ablation), but does NOT prove our system beats prior published work.

## On Adding GRU4Rec and BERT4Rec

### Should you add them?

Yes, eventually — they strengthen the story and both are already cited in `ref.bib`. But they are lower priority than fixing the SASRec framing issue.

### Priority order: GRU4Rec first, BERT4Rec second

**GRU4Rec** (`hidasi2016gru4rec` — already in ref.bib):
- Simpler to implement (GRU over item embedding sequence)
- Faster to train than Transformer-based models
- The codebase had scaffolding (`GRUSeqDQNStrategy`) but `app/services/rl_filter.py` is missing — it was deleted
- Implement as a clean content-based GRU: fixed BGE-M3 embeddings → project to 256-dim → GRU(hidden=256, layers=2) → score candidates by dot product with last hidden state
- Expected HR@10: somewhere between Content Baseline (0.4346) and SASRec (0.7655) — GRU captures sequential structure but weaker than self-attention

**BERT4Rec** (`sun2019bert4rec` — already in ref.bib):
- Bidirectional Transformer with masked item prediction (Cloze-style)
- Harder to implement correctly (mask-based training is different from causal)
- More impactful paper (higher citation count, stronger baseline)
- Would likely score close to SASRec (both Transformer-based; bidirectional vs causal is the main difference)
- Worth adding if there is time, but not essential if GRU4Rec is already present

### What to build for GRU4Rec

1. Create `app/services/gru4rec.py` — a `GRU4RecAgent` class with:
   - `ContentProjector` (same as in dif_sasrec.py, 1024→256)
   - `nn.GRU(input_size=256, hidden_size=256, num_layers=2, batch_first=True, dropout=0.2)`
   - Output: last hidden state → dot product with candidate embeddings
   - Training: same sampled-softmax loss as DIF-SASRec, `CAT_AUX_WEIGHT=0`

2. Create `scripts/train_gru4rec.py` (mirrors the DIF-SASRec training loop)

3. Add `GRU4RecStrategy` class to `evaluate_recommendation.py`

4. Run eval, add row to `chapter5_comparison_table.tex`
