\section{Improvements in Data Visualisation Module}
\label{sec:viz_improvements}

Three limitations were identified in the prior visualisation layer in Section~\ref{sec:viz_analysis}: synchronous rendering caused the page to freeze during slow API responses, no filtering or sorting controls existed, and the recommendation panel showed no indication of pipeline origin or personalisation state.
The revised frontend addresses all three through asynchronous loading patterns, dual recommendation panels with explicit pipeline attribution, and an inline training visualisation component.

\subsection{Asynchronous Rendering and Skeleton Loading}
\label{sec:skeleton_loading}

In the prior system, the React component tree rendered synchronously: the search view blocked the main thread while awaiting the API response, producing a visibly frozen interface during the 1{,}102 ms baseline latency window.
The revised implementation uses non-blocking async handlers for all data-fetching calls.
While a request is in flight, the result area is replaced by skeleton card placeholders that match the dimensions of the actual result cards.
This pattern applies to the search result list, the recommendation panels, and the profile data fetch.

\subsection{Dual Recommendation Panels}
\label{sec:dual_panels}

The prior recommendation panel was a single flat list with no indication of how or why items appeared.
The revised panel presents both pipelines in a single two-column view: People Also Buy on the left (top 10 from Pipeline~A) and You Might Like on the right (top 10 from Pipeline~B).
Each card carries a label showing which model produced it (Cleora + BGE-M3 or DIF-SASRec), so the source of each recommendation is visible.

A mode status indicator above the panel reflects the personalisation state from the \texttt{/recommend} endpoint.
Users with fewer than 5 interactions see a Discovery mode badge; once that threshold is crossed, it switches to a DIF-SASRec active badge and a toast notification confirms that personalised ranking is running.
New cards appearing after a refresh are highlighted for four seconds to make it clear the recommendations have updated.

\subsection{Online Training Visualisation}
\label{sec:training_viz}

A profile panel on the right side of the interface shows the online learning state in real time.
A radar chart (Engagement Signals) summarises five dimensions from the user's interaction history: click rate, cart rate, skip rate, interaction count, and recency.

Below the radar chart, a SASRec Loss sparkline plots the training loss history as a filled area chart.
A dashed divider marks the boundary between the pretraining phase and the online fine-tuning phase, since the two phases use different negative pool sizes and the loss scales differ.
When a click or cart event triggers a gradient step, the latest loss value appears briefly as a badge for 2.5 seconds, confirming that the model updated.

\subsection{Multimodal Search Interface}
\label{sec:multimodal_ui}

The search view accepts both text and image queries from a single input area.
An image drop zone below the text field accepts drag-and-drop or file-picker uploads and shows a preview thumbnail on load.
Text-only queries bypass the CLIP branch; image-only queries bypass the text encoder; both can be combined for fused retrieval.
Results replace the skeleton placeholders in place, with no page reload.

A dark mode toggle in the header applies a site-wide colour scheme switch using Tailwind CSS dark-mode variants, with no page reload required.
A Recently Viewed strip in the header shows book cover thumbnails from the user's interaction history.
Toast notifications confirm significant actions (search completion, cart addition, model update) using a 3-second auto-dismiss overlay in the top-right corner.
