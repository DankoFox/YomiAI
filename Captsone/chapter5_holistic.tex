\subsection{Holistic System Evaluation}
\label{subsec:holistic-eval}

Isolated pipeline metrics are insufficient to characterize a production recommendation
system: the true measure of effectiveness is how the unified system performs across the
full population of real users under realistic serving conditions.
The \texttt{recommend()} function in \texttt{app/api/routes/recommend.py} serves as the
system's routing decision point: users whose profile contains fewer than five prior
interactions (\texttt{COLD\_START\_THRESHOLD}~$=5$, defined in \texttt{app/config.py}) are
directed to a random-catalogue cold-start path, while all remaining users receive
personalized recommendations from the dual-pipeline engine.
In the offline evaluation over the \texttt{evaluation/eval\_users.json} dataset, 97.4\% of
test users received personalized recommendations; the remaining 2.6\% were excluded from
the HR@10 denominator because they either lacked sufficient interaction history, their target
test items fell outside the BGE-M3 FAISS flat index, or insufficient random negatives could
be drawn from the evaluation pool --- conditions identified in the \texttt{eval\_sampled()}
function (\texttt{scripts/benchmark/evaluate\_recommendation.py}, line~345).
This 97.4\% coverage demonstrates that the cold-start threshold and index coverage together
serve the overwhelming majority of real users without degradation.

The online fine-tuning mechanism --- Phase~2 of the system --- is implemented via the
\texttt{AgentPool} class (\texttt{app/services/agent\_pool.py}) and triggered by every
user click event through the \texttt{POST /interact} endpoint
(\texttt{app/api/routes/interact.py}, lines~70--78).
The pool maintains eight independent \texttt{DIFSASRecAgent} instances, each carrying
approximately 148~MB of per-user AdamW optimizer state and model weights, for a total VRAM
footprint of approximately 1.18~GB; a ninth concurrent request queues rather than errors,
ensuring zero dropped updates under bursty traffic.
On each click, the system borrows an agent, loads the user's persisted personal weights from
disk (\texttt{agent.load\_user()}), executes one gradient step on the observed
(state, action) transition via \texttt{recommend\_engine.train\_personal()}, and immediately
persists the updated weights (\texttt{agent.save\_user()}).
This per-click update loop allows the DIF-SASRec model to adapt from a cold (pre-session)
configuration to a warm (post-click) configuration within a single shopping session, yielding
an in-session HR@10 delta of [DELTA\_RESULT] between the zero-click and post-click states.
This uplift is practically significant for e-commerce deployment: a user who clicks on a
science-fiction title early in a session will receive increasingly science-fiction-aligned
recommendations within the same session, without waiting for an offline retraining cycle.

Table~\ref{tab:comparison} places the system in the context of sequential recommendation
baselines under an identical evaluation protocol (sampled, $N{=}99$ negatives, leave-last-out
split, 100{,}000 users, seed~$=42$).
The Content Baseline --- a BGE-M3 mean-profile vector without any sequential modelling ---
achieves HR@10~$=0.4346$, establishing the ceiling for non-sequential content retrieval.
Adding sequential self-attention under the SASRec architecture \cite{kang2018self} with the
same content embeddings raises HR@10 to 0.7655; this result is obtained via an ablation of
the pretrained DIF-SASRec model with the category attention stream disabled ($\alpha{=}0$),
so the comparison is controlled for training data and embedding space.
To provide a strictly independent comparison, we additionally trained SASRecF~\cite{kang2018self}
from scratch (\texttt{content\_only=True}, BGE-M3 content embeddings as the sole item
representation, same training data and 30-epoch protocol, no category stream or auxiliary loss),
achieving HR@10~$=0.7932$.
SASRecF corresponds to the early-fusion baseline in \citet{xie2022difsasrec}, where side
information is incorporated into the item embedding before attention rather than through
a decoupled stream.
The 2.8-point absolute improvement over the ablation confirms that the ablation row
underestimates SASRecF performance: when the category auxiliary loss shapes all parameters
during joint DIF-SASRec training, disabling the category stream at inference degrades
the learned content representations.
Enabling the full decoupled category-plus-content fusion of DIF-SASRec \cite{xie2022difsasrec}
--- Pipeline~B of our system --- achieves HR@10~$=0.7738$ ($+$0.0083 absolute over the
SASRec ablation), confirming the direction of category-decoupling benefit reported by
Xie et al.~\cite{xie2022difsasrec} (1.5--3.8\% across four Amazon product categories).
The absolute gain is smaller on Amazon Books, where category labels are coarse
(817 categories across 3~million items), consistent with findings in the original work
that category-stream benefits are largest in fine-grained taxonomies.
SASRecF (0.7932) outperforms DIF-SASRec (0.7738) in this domain, further corroborating
that coarse book categories limit the discriminative value of the category stream relative
to a model optimised entirely for content-based sequential patterns.
Pipeline~A, built on Cleora behavioral co-purchase graph embeddings re-ranked by BGE-M3,
achieves HR@10~$=0.9047$, substantially outperforming purely sequential approaches because
it captures co-purchase structure unavailable to a single-session sequential model.
The combination of routing coverage and Phase~2 online fine-tuning demonstrates that the
system's value exceeds the sum of its isolated pipeline scores: the full System A$\cup$B
achieves HR@10~$=0.9736$ and NDCG@10~$=0.5571$, while the AgentPool-backed online fine-tuning
further closes the cold-start gap that neither static pipeline can address alone.
