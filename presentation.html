01 — Motivation

The Problem at Scale

  • Scale: 3M+ books make manual discovery impossible — intelligent intermediation is required before the user types a query.
  • Unimodal blindness: Collaborative filtering ignores content; content-based methods ignore community co-purchase patterns; neither captures sequential intent.
  • Language exclusion: Most open-source encoders are English-only. Vietnamese users receive systematically lower quality results — a question of equitable access.
  • Latency budget: A recommendation API >1 second is not adopted in interactive apps. Accuracy and speed must co-optimize.

Prior System (Phase 1) Gaps

  • GRU-SeqDQN — HR@10 = 0.1031, barely above random (0.10)
  • Flat FAISS index — 612 ms P50 latency on 3M vectors
  • BLaIR encoder — Precision@10 = 0.025 on short Vietnamese queries
  • No multilingual support — English-only semantic search

03 — Architecture

Three-Tier Stack

Presentation Tier

  • React 19 + Vite — SPA with search, recommendation, and profile views
  • No business logic on frontend — pure HTTP REST consumer
  • TextIteratorStreamer popover, sparkline SVG for loss history

Application Tier

  • FastAPI + uvicorn (Python 3.11) — async/await for concurrent FAISS + Redis I/O
  • Routes: /search /recommend /interact /profile /auth /llm
  • Indices loaded once at startup via lifespan context manager

Data Tier

  • MongoDB — interaction logs & user profiles (schema-free)
  • Redis RPUSH — async write queue; decouples /interact hot path (<5 ms P50)
  • Parquet — metadata for 3M items, row-cache on demand

Section 04

Pipeline A
Cleora + BGE-M3

Behavioral co-purchase graph embeddings re-ranked by semantic profile similarity.

04 — Pipeline A

Behavioral Graph Retrieval — "People Also Buy"

  • Cleora embeddings trained on the co-purchase graph (375,280 items via Markov Random Walks). Converges in minutes vs. GPU-days for GNN alternatives.
  • User profile vector = mean-pool of BGE-M3 embeddings over click history. One consistent embedding space for profile and item.
  • Retrieval: FAISS inner-product search over Cleora index for top-50 neighbours → re-ranked by cosine similarity to profile vector.
  • Cold-start: Users with <5 interactions bypass both pipelines and receive items sampled uniformly from the Cleora catalogue.

Why Cleora over LightGCN / GraphSAGE?

  • LightGCN requires GPU memory proportional to neighbourhood depth at 375K-node scale
  • Cleora converges in minutes via iterative Markov smoothing
  • Production graph refit triggered by background Redis worker at configurable interaction threshold

Section 05

Pipeline B
DIF-SASRec

Decoupled Intent-Feature Sequential Recommendation Transformer with per-user online fine-tuning.

05 — Pipeline B

DIF-SASRec — Sequential Intent Modelling

  • Decoupled attention: Separate content and category attention streams exploit BGE-M3 embeddings directly. BERT4Rec's bidirectional masking is incompatible with online fine-tuning.
  • Architecture: 12.4M params, 4 transformer blocks, 8 heads, 512-dim hidden, max sequence 50 items (optimal from sensitivity study).
  • Content veto (τ=0.3): DIF-SASRec candidates with cosine similarity <0.3 to user BGE-M3 profile are filtered. Peak HR@10 at τ=0.3 (61% of candidates pass).
  • AgentPool: 8 isolated model instances share GPU, each holds own AdamW state (~148 MB VRAM). Per-user checkpoint loaded/saved per request.

05 — Pipeline B

DIF-SASRec Training: 3-Run Iterative Development

Run 1 — Apr 11 Baseline

  • 2.3M params, 2 blocks, 256-dim
  • 20K users · avg 40–50 clicks
  • HR@10 = 0.2973 (3× random baseline)
  • Under-capacity for the task

Run 2 — Regression

  • 12.4M params, 4 blocks, 512-dim
  • 200K users · avg only 21 clicks
  • HR@10 = 0.1950 — regression!
  • Root cause: AMP scheduler bug + sparse interactions below signal floor

Run 3 — Calibrated ✓

  • 100K users · avg 33.5 clicks
  • Per-epoch negative resampling (50K pool)
  • Batch 2048 + AMP + LR fix
  • HR@10 = 0.7745 — 161% improvement over Run 1
Key Lesson
Interaction density matters more than user count. A model with 5× more parameters trained on sparse data (Run 2) performs worse than a smaller model on dense data (Run 1). Training loss is misleading across runs with different negative sample sizes — always normalize by ln(K+1).

06 — Search

Multilingual Search: NLLB + BGE-M3 + Tantivy RRF

  • Stage 1 — Language detection: lingua library in <1 ms. English queries skip translation entirely.
  • Stage 2 — NLLB-200 translation: facebook/nllb-200-distilled-600M translates 19 non-English languages. Greedy pass first; quality gate retries with beam=4 if source tokens survive.
  • Stage 3 — Parallel encode & retrieve: BGE-M3 text encode + CLIP image encode run concurrently via anyio task group. FAISS HNSW + Tantivy BM25 → RRF fusion (k=60).
  • LRU cache: Translated queries cached up to 2,048 entries → repeated terms cost 0 ms.

Pipeline Complementarity Analysis

Both A∩B — 70,557 users (70.6%)
Pipeline A only — 19,909 users (19.9%)
Pipeline B only — 6,893 users (6.9%)
Neither — 2,641 users (2.6%)
Key Insight
The two pipelines are specifically compensatory: Pipeline A is the reliable floor for sparse users; Pipeline B adds signal for users who recently shifted reading genre.

User Archetypes Explained

  • Type A — Dense Readers (70.6%): High-activity users; both Cleora graph clusters and DIF-SASRec sequence agree on candidates.
  • Type B — Graph-Prominent (19.9%): Gift buyers, cross-genre readers — co-purchase community is informative but sequence is noisy.
  • Type C — Sequential Intent (6.9%): Recent genre shift detected by DIF-SASRec self-attention; not yet reflected in global graph.

08 — Conclusion

Summary & Future Work

What We Achieved

  • HR@10 = 0.9736 on 100K users — 124% above content baseline, 843% above legacy GRU-SeqDQN.
  • 18.6× search latency reduction: 1,102 ms → 59 ms warm E2E via HNSW + NLLB caching + parallel encode.
  • Multilingual support: Vietnamese long-query Precision@10 improved from 0.05 (BLaIR) to 0.55 (BGE-M3).
  • Complementary dual-pipeline: Pipeline A as floor for sparse users; Pipeline B captures recent sequential intent.

Limitations & Future Work

  • Cleora catalogue gap (45% of failures): 375K-item co-purchase graph misses long-tail items. Expand to full 3M index or add fallback BM25 path.
  • Checkpoint I/O bottleneck: Per-user checkpoint load/save = 1–2 s for new users. Candidate: async offloading or checkpoint sharding.
  • Cold veto for sparse users: Relax τ from 0.3 → 0.2 for users with <20 interactions (addresses 24% of failure cases).
  • Session segmentation: Cross-domain genre shifts (11% of failures) require explicit session boundary detection.
