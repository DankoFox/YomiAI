LLM Context Enrichment + Qwen2.5

Grounded book Q&A using Qwen2.5-1.5B-Instruct loaded locally. Three context sources are assembled before inference: local parquet description, Wikipedia summary, and Google Books snippet.

Context Enrichment — Fan-In to Prompt
① Local Parquet
metadata_repo.get_item(item_id) → description field + genre tags from item_metadata.parquet. Always available — no network call needed. Fastest source.
metadata_repo · disk
② Wikipedia API
fetch_wikipedia_summary(title, author) → Wikipedia REST API → first paragraph of article. LRU-cached by query. Adds author biography context and plot background.
Wikipedia API · async
③ Google Books API
_fetch_google_books(title, author) → Google Books REST API → editorial description snippet. Provides publisher-curated summary. Falls back to empty string on failure.
Google Books API · async
+

Qwen2.5-1.5B-Instruct
Local model, preloaded at startup. Receives assembled prompt with all three context sources. Runs in loop.run_in_executor() to avoid blocking the async event loop. System prompt: "You are a helpful book assistant."
Context sources fetched in parallel (asyncio tasks). Prompt assembled once all three are ready. Wikipedia + Google Books fetches are async I/O; parquet lookup is synchronous O(1).
Prompt Template
# System message:
You are a helpful assistant who answers questions about books.

# User message (assembled from 3 sources):
Here is information about the book "{title}" by {author}:

[Local description from parquet]
[Wikipedia summary paragraph]
[Google Books editorial snippet]

User question: {user_prompt}
Two Endpoints: Sync vs. Stream
POST /ask_llm — Synchronous
1
metadata_repo.get_item(item_id) → description + genre. Fetch Wikipedia + Google Books in parallel.
2
Assemble prompt string from all three context sources.
3
llm_service.generate(title, author, prompt, local_desc, text_encoder, genre) → Qwen2.5-1.5B inference via loop.run_in_executor().
4
Return {"response": str} — full text in one JSON response.
Blocks until full generation completes. Suitable for programmatic use.
POST /ask_llm_stream — SSE Token Stream
1
Same context enrichment as sync version.
2
llm_service.generate_stream() → async generator yields text chunks token-by-token via loop.run_in_executor() + queue handoff.
3
FastAPI returns StreamingResponse(content=gen, media_type="text/event-stream").
4
Browser reads via ReadableStream in api.askLLMStream(). Chunks appended to UI as received.
Lower perceived latency — first tokens appear in ~200ms vs waiting for full response.

Context Enrichment Functions (app/services/llm.py)
  • A
    fetch_book_context(title, author, item_id) — top-level coordinator. Calls fetch_wikipedia_summary() and _fetch_google_books() concurrently via asyncio tasks. Merges with local parquet description.
  • B
    fetch_wikipedia_summary(title, author) — Wikipedia API /api/rest_v1/page/summary/{title}. Cleans HTML tags. Falls back to empty string. LRU-cached via @lru_cache on normalized query.
  • C
    _fetch_google_books(title, author) — Google Books API volumes?q={title}+inauthor:{author}. Extracts volumeInfo.description from first result. Falls back to empty string on HTTP/parse errors.
  • D
    ensure_loaded() — lazy-loads Qwen2.5 tokenizer + model on first LLM call if not already in memory. Runs once per process lifetime. Also calls _build_wiki_queries() to pre-warm common author queries.
