POST /search app/api/routes/search.py Multimodal
Mode 1: Active search. Body: {"query": str, "image_base64": str|null, "top_k": int}
① NLLB Translation
VI → EN if Vietnamese detected via Lingua. Adds ~5ms cached, ~274ms cold.
→
② Parallel Encoding
BGE-M3 text → [1024] and CLIP image → [512] run concurrently via anyio.TaskGroup.
→
③ Dual FAISS Search
HNSW text index + CLIP HNSW index searched in parallel. BM25 Tantivy rerank via RRF fusion.
→
④ Metadata Hydration
Each ASIN → metadata_repo.get_item(): title, author, genre, image URL, score.
  • 1
    translate_to_en(query) — NLLB-600M (thread executor). Skips if EN.
  • 2
    Parallel: encode_text(query, text_encoder) → [1024] float32 / encode_image_b64(image_b64, clip_model) → [512].
  • 3
    search_engine.search(user_id, text_vec, image_vec, query, top_k) → HNSW FAISS + Tantivy BM25 + RRF.
  • 4
    metadata_repo.get_item(asin) for each result → adds title, author, genre, cover_color, image_url.
  • 5
    Returns {"results": [...], "total": int, "live_encoding": bool, "query": str}.
BGE-M3 CLIP FAISS HNSW Tantivy BM25 NLLB translate
GET /recommend?user_id= app/api/routes/recommend.py Dual Pipeline
Mode 2: Personalised recommendations. Returns people_also_buy (Pipeline A) and you_might_like (Pipeline B). Cold-start users (<5 clicks) get 20 random catalogue items.
Pipeline A — People Also Buy · Cleora + BGE-M3
  1. Cleora FAISS: cleora_profile [1024] → IndexFlatIP search → behavioral candidates
  2. Seed expansion: last 5 recent_interactions → get_behavioral_candidates() co-purchase neighbors
  3. Content veto: text_profile @ item_text ≥ 0.3 OR visual_profile @ item_clip ≥ 0.3
  4. Rank: sort survivors by text_score desc → top 10
Pipeline B — You Might Like · DIF-SASRec
  1. HNSW KNN: text_profile [1024] → 200 content candidates (unseen only)
  2. Content veto: same τ=0.3 threshold, filters both text and visual similarity
  3. DIF-SASRec score: agent.get_candidate_scores(click_seq, cat_ids, candidates) → dot products intent @ cand_proj
  4. Normalise & return: min-max scale → top 10
  • 1
    profile_manager.get_profile(user_id). If len(clicks) < 5: cold-start random sample.
  • 2
    agent_pool.borrow() → agent.load_user(user_id): load per-user .pt checkpoint from disk.
  • 3
    recommend_engine.recommend_for_user(user_id, agent, top_k=10) → runs both pipelines.
  • 4
    Redis blocked-set filter: removes any ASIN the user marked "not_interested".
  • 5
    profile_manager.log_recommendation(user_id, all_rec_ids) → persists to MongoDB.
  • 6
    metadata_repo.get_item(asin) for every rec → enriches with title/author/genre/image/score.
  • 7
    Returns {"people_also_buy": [...], "you_might_like": [...], "combined": [...], "mode": "personalized"|"cold_start"}.
DIF-SASRec FAISS HNSW + Flat MongoDB Redis blocked-set
POST /interact app/api/routes/interact.py Online Training
Log a user action and trigger one DIF-SASRec gradient step. Body: {"user_id", "item_id", "action": "click"|"skip"|"not_interested", "session_id", "source"}
  • 1
    not_interested: writes item_id to Redis set user:{uid}:blocked. Returns immediately — no training.
  • 2
    Capture click_seq_before = profile_manager.get_click_sequence(user_id) before profile update (this is the training input sequence st).
  • 3
    click: profile_manager.log_click(user_id, item_id) → appends to clicks deque, recomputes text_profile / visual_profile / cleora_profile (exponential decay weighted average), persists to MongoDB. skip: appends to purchases list only, no embedding update.
  • 4
    Push raw interaction to Redis list "nba_interactions" → background worker drains to MongoDB.
  • 5
    If action == "click" AND click_seq_before non-empty: agent_pool.borrow() → agent.load_user() → recommend_engine.train_personal(user_id, item_id, agent, click_seq_before) → one gradient step (sampled softmax + category auxiliary loss) → agent.save_user() persists .pt checkpoint to disk.
  • 6
    Returns {"status": "ok", "sasrec_loss": float|null}.
DIF-SASRec online train MongoDB profile update Redis queue + blocked-set disk .pt checkpoint

  • 2

4 · Service Layer Map
active_search.py — ActiveSearchEngine
Used by: POST /search
Inputs: text_vec [1024], image_vec [512], raw query string
Steps:
  1. HNSW BGE-M3 search + HNSW CLIP search in parallel
  2. Tantivy BM25 keyword search on raw query
  3. RRF fusion of all three ranked lists
Returns: ranked (asin, score_dict) list
passive_recommend.py — PassiveRecommendationEngine
Used by: GET /recommend, POST /interact
Key methods:
  • recommend_for_user() — orchestrates both pipelines
  • collaborative_filter() — Cleora FAISS + seed expansion
  • content_verify() — τ=0.3 dot product veto (shared)
  • _personal_recommend() — Pipeline B DIF-SASRec scoring
  • train_personal() — one online gradient step
Note: Engine holds no model state; agent is always borrowed from AgentPool.
dif_sasrec.py — Model Stack
Classes (bottom → top):
  • ContentProjector: Linear(1024→512) + LayerNorm + Dropout
  • DIFAttentionLayer: Dual-stream Q/K (content + category), fused attention score, content V
  • DIFSASRecBlock: pre-norm attention + FFN (512→1024→512) with residuals
  • DIFSASRecModel: 4 blocks + position emb + category emb + category_head (aux task)
  • DIFSASRecAgent: model + AdamW optimizer + load/save/train_step/get_candidate_scores
agent_pool.py — AgentPool
Purpose: Prevents race conditions for concurrent requests.
Pool size: 8 agents × ~148 MB ≈ 1.18 GB VRAM
Pattern: async with pool.borrow() as agent:
New user: resets to _pretrained_state (CPU snapshot, never mutated)
Returning user: loads personal {user_id}_dif_sasrec.pt
llm.py — Qwen2.5 Assistant
Used by: POST /ask_llm, POST /ask_llm_stream
Model: Qwen2.5-1.5B-Instruct (local, preloaded at startup)
Context sources:
  • Local parquet description + genre
  • Wikipedia summary (fetched via API)
  • Google Books API snippet
Functions: generate() (sync) / generate_stream() (async generator)
category_encoder.py — CategoryEncoder
Purpose: Maps book ASINs → leaf category integer ID
Source: categories column of item_metadata.parquet
ID 0: PAD · ID 1: UNK · ID 2+: sorted leaf names
Lookups:
  • get_category_id(asin) → int O(1)
  • encode_sequence(asin_list) → [int, ...]
Saved as: data/category_vocab.json

8 · End-to-End: User Clicks a Book

Complete trace from user action to model update.

① Browser — handleInteract(book, "click")
Optimistic update: prepend to interactions state immediately. Call api.interact(userId, book.id, "click").
→
② POST /interact — interact.py
Capture click_seq_before. Update profile. Push to Redis queue. Trigger training.
③ profile_manager.log_click()
Append to clicks. Recompute text/visual/cleora profile with exponential decay. Upsert MongoDB.
→
④ Redis queue push
Raw event → "nba_interactions" list. Background _log_worker drains to MongoDB analytics collection asynchronously.
⑤ agent_pool.borrow() → agent.load_user()
Load per-user .pt checkpoint (or pretrained snapshot for new users). Agent isolated from all other concurrent requests.
→
⑥ agent.train_step(click_seq_before, item_asin)
Build tensors → forward pass → intent [512] → score 1 pos + 512 neg → sampled softmax + category aux loss → backprop → AdamW step.
⑦ agent.save_user()
Write updated model_state + optimizer_state + loss_history to data/profiles/{user_id}_dif_sasrec.pt.
→
⑧ Response → Browser updates
{"status":"ok","sasrec_loss":float}. Browser appends loss to sparkline. Every 3rd click triggers loadRecs() after 800ms to refresh recommendations.
9 · Dependency Injection Pattern
# app/api/dependencies.py def get_container(request: Request) → AppContainer: return request.app.state.container def require_ready(container: AppContainer = Depends(get_container)): if not container.ready: raise HTTPException(503, detail="Service not ready") return container # Usage in any route: async def recommend(user_id: str, container: AppContainer = Depends(require_ready)): retriever = container.retriever # FAISS indexes agent_pool = container.agent_pool # DIF-SASRec pool ...

All routes are stateless — they read from the shared container but never mutate it. Per-user state lives in MongoDB (profile) and on disk (.pt files). The container fields are write-once at startup.
