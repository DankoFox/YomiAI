Full Recommendation Flow — GET /recommend

Orchestrates both Pipeline A (Cleora behavioral) and Pipeline B (DIF-SASRec sequential). Applies cold-start fallback, Redis blocked-set filter, deduplication, and metadata hydration.

Step 1 — Cold-Start Check
Warm Path — Personalized
len(profile.clicks) ≥ 5
User has enough interaction history. Run both pipelines. Borrow agent from pool. Return mode: "personalized".
clicks ≥ 5?

Cold-Start Path
len(profile.clicks) < 5
Not enough history. Return 20 random catalogue items via random ASIN sample. Return mode: "cold_start". Skip both pipelines.
Step 2 — Dual Pipeline (Warm Path)
Pipeline A — People Also Buy (Cleora)
1
Cleora IndexFlatIP search on cleora_profile [1024] → behavioral neighbors from 375k co-purchase graph.
2
Seed expansion: last 5 recent_interactions → additional co-purchase neighbors. Union candidate set.
3
Content veto τ=0.3: filter by text_profile OR visual_profile cosine similarity.
4
Sort by text_profile · item_text_vec → top-10 people_also_buy.

1

2
Content veto τ=0.3 on same threshold (shared logic with Pipeline A).
3
agent.get_candidate_scores(click_seq, cat_ids, candidates) → intent [512] dot-product scores.
4
Min-max normalize → top-10 you_might_like.
Steps 3–6 — Post-Pipeline Processing
⚡
Redis Blocked-Set Filter
For each recommended ASIN: check Redis set user:{uid}:blocked. Remove any item the user marked "not_interested". O(1) per ASIN lookup. Prevents dismissed items from re-surfacing.
📋
Log Recommendations
profile_manager.log_recommendation(user_id, all_rec_ids) → appends combined ASIN list to recent_recs in MongoDB profile for analytics and future deduplication.
🔍
Metadata Hydration
metadata_repo.get_item(asin) for every recommendation → enriches with title, author, genre, description, cover_color, image_url, pipeline score. All 20+ items hydrated in a single pass.
🔗
Combined List
Union of people_also_buy + you_might_like deduplicated by ASIN → combined list. Preserves both per-pipeline lists separately for the frontend to render in two sections.
Detailed Step Trace
  • 1
    profile_manager.get_profile(user_id). Check len(profile.clicks) < 5 → if true, cold-start random sample of 20 ASINs, hydrate, return immediately with mode: "cold_start".
  • 2
    agent_pool.borrow() (async context manager) → agent.load_user(user_id): load personal .pt checkpoint from data/profiles/ or pretrained snapshot for first-time users.
  • 3
    recommend_engine.recommend_for_user(user_id, agent, top_k=10) → runs Pipeline A (collaborative_filter) and Pipeline B (_personal_recommend) sequentially. Returns (people_also_buy, you_might_like).
  • 4
    Redis filter: await redis.smembers(f"user:{uid}:blocked") → set difference removes blocked ASINs from both lists.
  • 5
    profile_manager.log_recommendation(user_id, combined_asins) → MongoDB upsert appends to recent_recs.
  • 6
    Metadata hydration loop: [metadata_repo.get_item(asin) for asin in all_recs]. Build response with per-pipeline scores and combined list.
  • 7
    Return JSON. Agent automatically returned to AgentPool queue by async with context manager exit, making it available for the next request.
